# TEVULY · Architecture

> Phase A — Edge-native catalog on Cloudflare (Worker + D1 + Assets).
> Phases B–D (Printful/PAS, PayPal, fulfillment, email) are scaffolded as
> explicit seams and are **not** deployed yet.

## 1. Topology

```
                    ┌──────────────────────────────┐
   Browser ───────▶ │  Cloudflare Worker tevuly-edge│
                    │  ─ Hono router (/api/*)      │
                    │  ─ Assets binding (SPA)      │
                    └──────┬───────────────────────┘
                           │
              ┌────────────┴────────────┐
              │  D1 (SQLite) tevuly-d1  │  ← catalog, carts, orders*, jobs, webhooks
              └─────────────────────────┘
       R2 tevuly-media (paid seam)   DO CartManagerDO (paid seam)
       Queues catalog/order (paid)   Cron */5 * * * * (jobs pickup, free tier)
```

* The SPA is compiled by Vite into `dist/` and served from the SAME Worker
  via the `[assets]` binding — single origin, single deploy.
* `/api/*` never hits asset routing; unknown `/api` paths return structured
  404 JSON, not `index.html`.

## 2. Free vs paid runtime

| Capability   | Free tier (default)                     | Paid seam (wrangler.toml)              |
|--------------|------------------------------------------|----------------------------------------|
| Cart         | D1 `carts`/`cart_items` w/ optimistic `version` | `CartManagerDO` (SQLite DO)        |
| Async work   | D1 `jobs` + `*/5` cron poll              | Queues `catalog-sync`/`order-fulfillment` + DLQs |
| Media        | R2 binding present, unused in Phase A    | R2 `tevuly-media`                      |

The Worker code never assumes paid bindings exist: `WorkerEnv` types them
optional and feature adapters check binding presence at use-time.

## 3. Data conventions (enforced everywhere)

* money = integer cents; timestamps = INTEGER unix seconds; booleans 0/1.
* UUIDs generated by the Worker (`crypto.randomUUID`); D1 has no
  AUTOINCREMENT — TEXT primary keys keep migrations deterministic.
* JSON-in-TEXT documented columns (`images_json`, `tags_json`, …).
* `cart_items.variant_id NOT NULL` + `UNIQUE(cart_id, variant_id)`:
  every cart line is bound to a concrete print variant, so uniqueness is
  sound (a cart can't hold the same variant twice).
* `orders` store immutable shipping/price snapshots; profile edits never
  rewrite history.

## 4. No fabricated ratings

`products.ratings_verified` (0/1) gates the SEO aggregate-rating block.
Seed data carries the catalog's historical display metrics with
`ratings_verified = 0`, so **JSON-LD never emits `AggregateRating` for
unverified numbers** (covered by tests).

## 5. API surface (Phase A)

| Method | Path                   | Notes                                              |
|--------|------------------------|----------------------------------------------------|
| GET    | `/api/health`          | `ok`/`degraded` + D1 reachability                   |
| GET    | `/api/products`        | page/limit/category/sort/q/featured/trending (zod-validated whitelist) |
| GET    | `/api/products/:slug`  | detail + print variants + SEO payload               |

Error envelope (single shape, always):

```json
{ "error": { "code": "...", "message": "...", "requestId": "..." } }
```

## 6. Security posture (implemented)

* CORS allowlist only (no wildcard); disallowed origins get structured 403.
* Parameterized SQL only; sort/filter keys pass a zod whitelist before they
  can influence any query; ORDER BY fragments come from a constant map.
* Per-isolate fixed-window rate limit (429). Edge-level rate limiting is a
  Paid-tier seam.
* Request-ID on every response (`x-request-id`) and integrated in log/error
  envelopes; logs redact `authorization`, `cookie`, `set-cookie`, `x-api-key`.
* Secrets are injected via `wrangler secret put` only — never in code, vars
  or the repo (see SECURITY.md).

## 7. Repository layout

```
worker/
  src/
    index.ts             # Hono app + entrypoint (fetch + scheduled no-op guard)
    env.ts               # zod-validated runtime config
    infra/               # cors, errors, logger, rateLimit, requestId, context
    db/                  # D1 client + repositories
    services/            # catalog service, pure query validation, SEO builder
    routes/              # health, products
    data/seed.ts         # deterministic seed dataset (provenance of catalog)
    test/unit/           # pure unit tests (node pool)
    test/integration/    # full-worker + D1 integration tests (vitest-pool-workers)
  migrations/0001_init.sql
  seeds/products.sql     # generated by tools/build-seed.ts (idempotent)
  tools/build-seed.ts    # seed SQL generator (bun run seed:build)
  wrangler.free.toml     # deploy target used today (free tier)
  wrangler.toml          # paid target with DO/Queues seams
src/                    # SPA (Vite + React), consumes /api via use-catalog
```

## 8. Verification ladder

1. `npm run typecheck` (worker) — strict TS, zero `any`-casts into public APIs.
2. `npm run test:unit` — 31 pure tests (query validation, SEO honesty, error
   envelopes, redaction, rate limiter).
3. `npm run test:integration` — full worker through `@cloudflare/vitest-pool-workers`
   (run in CI; requires workerd — see DEPLOYMENT.md note about sandbox limits).
4. `wrangler dev` smoke + real deploy runbook (DEPLOYMENT.md).
